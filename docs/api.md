# API Documentation\n\n## Process Management API\n\nRESTful API for managing business processes, following PYX4 methodology for process modeling.\n\n### Base URL\n```\nhttp://localhost:3001\n```\n\n### Authentication\n> **Note**: Authentication is not yet implemented. All endpoints currently use a mock user system.\n\n## Endpoints\n\n### Processes\n\n#### GET /processes\nRetrieve a paginated list of processes with optional filtering.\n\n**Query Parameters:**\n- `page` (number, optional): Page number (default: 1)\n- `limit` (number, optional): Items per page (default: 10)\n- `search` (string, optional): Search in name, description, or author\n- `type` (enum, optional): Process type (`PROCESSUS`, `PROCEDURE`, `INSTRUCTION`)\n- `status` (enum, optional): Process status (`DRAFT`, `REVIEW`, `APPROVED`, `PUBLISHED`, `ARCHIVED`)\n- `level` (number, optional): Process level (1, 2, or 3)\n- `parentId` (UUID, optional): Parent process ID\n- `createdById` (UUID, optional): Creator user ID\n- `sortBy` (string, optional): Field to sort by\n- `sortOrder` (string, optional): Sort order (`asc` or `desc`)\n\n**Response:**\n```json\n{\n  \"data\": [\n    {\n      \"id\": \"clp123...\",\n      \"name\": \"Employee Onboarding Process\",\n      \"description\": \"Complete process for onboarding new employees\",\n      \"type\": \"PROCESSUS\",\n      \"level\": 1,\n      \"status\": \"PUBLISHED\",\n      \"version\": 1,\n      \"authorName\": \"Alice Johnson\",\n      \"createdAt\": \"2024-01-15T10:00:00Z\",\n      \"createdBy\": {\n        \"id\": \"user123\",\n        \"name\": \"Alice Johnson\",\n        \"email\": \"alice@company.com\"\n      },\n      \"_count\": {\n        \"children\": 2,\n        \"versions\": 1,\n        \"comments\": 3\n      }\n    }\n  ],\n  \"meta\": {\n    \"page\": 1,\n    \"limit\": 10,\n    \"total\": 25,\n    \"totalPages\": 3,\n    \"hasNext\": true,\n    \"hasPrev\": false\n  }\n}\n```\n\n#### POST /processes\nCreate a new process.\n\n**Request Body:**\n```json\n{\n  \"name\": \"New Process Name\",\n  \"description\": \"Process description\",\n  \"type\": \"PROCEDURE\",\n  \"level\": 2,\n  \"parentId\": \"clp123...\", // optional\n  \"authorName\": \"John Doe\",\n  \"changesLog\": \"Initial creation\" // optional\n}\n```\n\n**Response:** Process object (201 Created)\n\n#### GET /processes/:id\nRetrieve a specific process with full details and relationships.\n\n**Response:**\n```json\n{\n  \"id\": \"clp123...\",\n  \"name\": \"Employee Onboarding Process\",\n  \"description\": \"Complete process for onboarding new employees\",\n  \"type\": \"PROCESSUS\",\n  \"level\": 1,\n  \"status\": \"PUBLISHED\",\n  \"version\": 1,\n  \"publishedAt\": \"2024-01-15T10:00:00Z\",\n  \"authorName\": \"Alice Johnson\",\n  \"createdAt\": \"2024-01-15T10:00:00Z\",\n  \"parent\": null,\n  \"children\": [\n    {\n      \"id\": \"clp456...\",\n      \"name\": \"HR Documentation Setup\",\n      \"type\": \"PROCEDURE\",\n      \"level\": 2\n    }\n  ],\n  \"createdBy\": {\n    \"id\": \"user123\",\n    \"name\": \"Alice Johnson\",\n    \"email\": \"alice@company.com\"\n  },\n  \"versions\": [\n    {\n      \"id\": \"ver123\",\n      \"version\": 1,\n      \"status\": \"PUBLISHED\",\n      \"releasedAt\": \"2024-01-15T10:00:00Z\"\n    }\n  ],\n  \"_count\": {\n    \"comments\": 5,\n    \"assignments\": 2,\n    \"versions\": 1\n  }\n}\n```\n\n#### PATCH /processes/:id\nUpdate a process.\n\n**Request Body:** Partial process object (same structure as POST)\n\n**Response:** Updated process object\n\n#### DELETE /processes/:id\nDelete a process.\n\n**Response:** 204 No Content\n\n**Business Rules:**\n- Cannot delete processes with child processes\n- Cannot delete archived processes\n\n#### GET /processes/roots\nRetrieve all root processes (level 1, no parent).\n\n**Response:** Array of process objects with children count\n\n#### GET /processes/:id/hierarchy\nRetrieve the complete hierarchy tree starting from a root process.\n\n**Response:**\n```json\n{\n  \"id\": \"clp123...\",\n  \"name\": \"Employee Onboarding Process\",\n  \"type\": \"PROCESSUS\",\n  \"level\": 1,\n  \"children\": [\n    {\n      \"id\": \"clp456...\",\n      \"name\": \"HR Documentation Setup\",\n      \"type\": \"PROCEDURE\",\n      \"level\": 2,\n      \"children\": [\n        {\n          \"id\": \"clp789...\",\n          \"name\": \"Contract Preparation\",\n          \"type\": \"INSTRUCTION\",\n          \"level\": 3,\n          \"children\": []\n        }\n      ]\n    }\n  ]\n}\n```\n\n#### PATCH /processes/:id/status\nUpdate process status (workflow management).\n\n**Request Body:**\n```json\n{\n  \"status\": \"APPROVED\"\n}\n```\n\n**Response:** Updated process object\n\n**Status Transitions:**\n- `DRAFT` → `REVIEW` → `APPROVED` → `PUBLISHED` → `ARCHIVED`\n- Cannot modify archived processes\n- Must be approved before publishing\n\n## Data Models\n\n### Process Types\n- `PROCESSUS`: High-level business process (Level 1)\n- `PROCEDURE`: Detailed procedure (Level 2)\n- `INSTRUCTION`: Specific work instruction (Level 3)\n\n### Process Status\n- `DRAFT`: Initial creation and editing\n- `REVIEW`: Under review by stakeholders\n- `APPROVED`: Approved for publication\n- `PUBLISHED`: Active and in use\n- `ARCHIVED`: No longer active\n\n### Role Types\n- `INTERNE`: Internal company role\n- `EXTERNE`: External contractor/consultant role\n\n## Error Handling\n\n### Standard Error Response\n```json\n{\n  \"statusCode\": 400,\n  \"message\": \"Validation failed\",\n  \"error\": \"Bad Request\",\n  \"details\": [\n    {\n      \"field\": \"name\",\n      \"message\": \"Name is required\"\n    }\n  ]\n}\n```\n\n### Common Error Codes\n- `400`: Bad Request - Validation errors\n- `404`: Not Found - Resource doesn't exist\n- `409`: Conflict - Duplicate resource\n- `422`: Unprocessable Entity - Business rule violation\n- `500`: Internal Server Error\n\n## Business Rules\n\n### Process Hierarchy\n- Child processes must have a level greater than their parent\n- Cannot create circular dependencies\n- Root processes (Level 1) have no parent\n\n### Naming\n- Process names must be unique within the same version\n- Names are case-sensitive\n\n### Status Management\n- Archived processes cannot be modified\n- Published processes create a new version for modifications\n- Status transitions follow a specific workflow\n\n### Deletion\n- Cannot delete processes with child processes\n- Cannot delete processes referenced by other entities\n- Soft delete recommended for published processes\n\n## Examples\n\n### Create a Main Process\n```bash\ncurl -X POST http://localhost:3001/processes \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"name\": \"Customer Support Process\",\n    \"description\": \"End-to-end customer support workflow\",\n    \"type\": \"PROCESSUS\",\n    \"level\": 1,\n    \"authorName\": \"Support Manager\"\n  }'\n```\n\n### Get Processes with Filtering\n```bash\ncurl \"http://localhost:3001/processes?type=PROCEDURE&status=PUBLISHED&limit=5&page=1\"\n```\n\n### Update Process Status\n```bash\ncurl -X PATCH http://localhost:3001/processes/clp123.../status \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\"status\": \"APPROVED\"}'\n```
